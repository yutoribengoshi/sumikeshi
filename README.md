# sumikeshi（すみけし）

準備書面・陳述書・証拠などの Word・テキスト・PDF から、人の名前・会社名・住所・電話番号・メールアドレス・口座番号・生年月日・事件番号などを探し、記号に置き換えるか黒く塗りつぶすためのコマンドです。Windows の PowerShell でも、Mac のターミナルでも動きます。

文書をインターネットに送らず、手元の PC の中だけで処理します。生成AI も使いません。規則と（入れてあれば）形態素解析の辞書で探します。

まだ試作（v0.1）です。伏せた文書は、外に出す前に必ず全文を目で読んでください。

## 流れ

全部を機械任せにはせず、次の3段で進めます。

1. 洗い出し（`scan`）: 伏せる候補を探して、Excel の一覧にする
2. 確認: 一覧を Excel で開き、伏せるもの（○）と伏せないもの（×）を決め、置換後の記号を直す。見落としがあれば行を足す
3. 適用（`apply`）: 一覧の ○ の行を伏せた新しいファイルを作り、残りがないか機械で検査する

元のファイルは書き換えません。伏せた文書は `○○_匿名.docx` のように別の名前で保存します。ファイル名に名前が入っていれば、ファイル名も伏せます。

```
準備書面.docx ──scan──▶ 準備書面_候補.xlsx（Excel で ○/× を直す）
             ──apply─▶ 準備書面_匿名.docx ＋ 準備書面_匿名_検査.txt
```

## Windows の EXE 版（Python を入れずに使う）

[Releases](https://github.com/yutoribengoshi/sumikeshi/releases) から `sumikeshi-windows.zip` を取り、展開します（リリース前の試作は [Actions](https://github.com/yutoribengoshi/sumikeshi/actions) の各実行の「Artifacts」にあります。GitHub へのログインが要ります）。

ファイルを `sumikeshi.exe` のアイコンの上に重ねて（ドラッグ＆ドロップして）使います。

1. Word・テキストの文書を重ねる → 候補一覧（`〜_候補.xlsx`）ができて Excel で開く
2. 一覧の採否（○/×）と置換後を直して保存する
3. 直した一覧を重ねる → `〜_匿名.docx` と検査の報告ができる

- 初めて開くと「Windows によって PC が保護されました」と出ます（署名の無いプログラムへの警告）。「詳細情報」→「実行」で開きます
- 形態素解析（Sudachi）の辞書を入れてあるので、展開後は数百MBになります
- EXE の版は PDF に対応していません（PDF は下の Python 版で扱えます）
- `sumikeshi.exe` は同じフォルダの `_internal` と一緒に動きます。exe だけを別の場所に移さないでください

## 入れ方（Python 版）

Python 3.9 以上が要ります。Windows なら python.org の Windows 版を入れ、PowerShell で `py --version` が動くことを確かめてください。

このフォルダで次を実行します（Mac は `py` を `python3` に読み替えてください）。

```
py -m pip install .
```

精度を上げたいとき、PDF も扱いたいときは、追加で入れます。

```
py -m pip install ".[all]"
```

- `sudachipy` と `sudachidict_core`（形態素解析）: 文中に姓だけ・名前だけで出てくる人（「田中は、同日、」）を拾えるようになります。入れなくても動きますが、そのときは「原告」「様」「弁護士」のような手がかりのある名前しか拾いません
- `pymupdf`: PDF の墨消しに要ります。ライセンスは AGPL です

## 使い方

### 1. 洗い出し

```
sumikeshi scan 準備書面.docx
```

同じフォルダに `準備書面_候補.xlsx` ができます。複数のファイルをまとめて渡すと、1つの一覧になり、同じ人には全部のファイルで同じ記号が振られます（訴状・準備書面・陳述書を一緒に伏せるとき）。

```
sumikeshi scan 訴状.docx 準備書面1.docx 陳述書.docx
sumikeshi scan 案件フォルダ
```

`sumikeshi` が見つからないと言われたら、`py -m sumikeshi scan …` と打ってください。

### 2. 一覧を直す

`準備書面_候補.xlsx` を Excel で開きます。

| 列 | 意味 |
|---|---|
| 採否 | ○ は伏せる、× は伏せない。空欄は ○ として扱う |
| 種別 | 人名・代理人・法人・住所・電話・メール・郵便番号・口座・生年月日・番号・車両番号・事件番号・URL・物件 |
| 原文 | 本文で探す語。空白は詰めて書けば、本文の「山　田　太　郎」のような字間の空白にも当たる |
| 置換後 | 置き換える記号。書き換えてよい。■ だけにすると、その字数分の ■ で墨消しする |
| 件数・文脈 | 本文で何回当たったか、最初の1回の前後 |
| 確度・根拠 | 何を手がかりに拾ったか（「原告」の後、「様」の前、形態素など） |

見落としがあれば、一覧の下に行を足します（採否・原文・置換後の3つで足ります）。

### 3. 適用と検査

```
sumikeshi apply --list 準備書面_候補.xlsx
```

`準備書面_匿名.docx` と、検査の報告 `準備書面_匿名_検査.txt` ができます。検査で原文の残りが見つかると、出力の名前が `_匿名_不合格` になります。

一覧を直さずに伏せるだけなら、`auto` で2つを続けて行えます。

```
sumikeshi auto 準備書面.docx
```

### 置き換え方を選ぶ

`scan`（または `auto`）に `--style` を付けます。

| `--style` | 例 | 向いている場面 |
|---|---|---|
| `xy`（既定） | 原告側の人・会社はＸ、被告側はＹ、ほかはＡ・Ｂ・Ｃ（会社はＡ社） | 事例の検討・研修の教材・AI への相談 |
| `abc` | 全部Ａ・Ｂ・Ｃ | 当事者の立場も伏せたいとき |
| `maru` | 全部○○ | 書式の見本 |
| `kuro` | 字数分の■（字間の空白は残す） | 証拠の墨消し・開示の黒塗り |

住所は既定で市区町村まで残します（「東京都新宿区○○」）。`--address pref` で都道府県まで、`--address all` で全部伏せます。

伏せない名前（自分の事務所名など）は `--keep` で渡すと、一覧で × になります。

```
sumikeshi scan 準備書面.docx --keep "甲野法律事務所,乙野次郎"
```

## 何を拾うか

- 人名: 役割語の後（原告・被告・申立人・相手方・訴外・証人・代表取締役・弁護士 など）、敬称・肩書きの前（様・殿・氏・さん・先生・社長・部長 など）、氏名の欄、「（以下「原告」という。）」の定義、記名だけの行、「妻の花子」「母の山田キヨ子」のような家族・知人の呼び方の後、形態素解析（入れてあれば）
- 字間の空白（「山　田　太　郎」）、目に見えない文字（ゼロ幅の空白・異体字セレクタ・ソフトハイフンなど）、々（佐々木）、異体字（髙・﨑・關・𠮷 など）、康熙部首、全角半角、半角カナ、濁点が分かれた形（macOS の NFD）に当たる
- フルネームから姓・名を切り出し、姓だけ・名だけの出現にも同じ記号を振る。読み（フリガナの欄、名前の後ろの括弧の「ヤマダ　タロウ」「Taro Yamada」）も同じ記号にする。Sudachi を入れてあれば、漢字の名前からカナ・ひらがな・ローマ字の読みを作って当てる
- 法人: 株式会社・有限会社・合同会社・一般社団法人などの付いた名、「〜建設」「〜商事」「〜クリニック」「〜屋」などの屋号、英文の社名（Co., Ltd. など）。「（以下「みどり建設」という。）」の略称と「(株)」「㈱」の書き方は正式名と同じ記号にする
- 住所（市区町村より後・建物名と部屋番号まで。次の行に送られた建物名、「東京都新宿区西新宿に居住」のような番地の無い書き方、札幌の「北1条西2丁目」も）、物件目録の地番・家屋番号
- 電話・FAX（区切りが「—」「.」でも、漢数字でも）、メールアドレス、URL、郵便番号（〒が無くても住所の前なら）、口座番号（「口座番号は…」も）、カード番号、生年月日（「…に生まれました」「生年月日は…」「漢数字」も）、個人番号・免許証番号・保険証番号など、車両の登録番号、事件番号（「令和○年（ワ）第○○号」の形にする）
- 本文にもとからある伏せ字（「Ａ社」「Ｂ」）と同じ記号は使わない

判例の引用（「最判平成２０年６月４日民集…〔○○事件〕」「東京地方裁判所平成３０年５月１０日判決（平成２８年（ワ）第…号）」）、条文（「民法７０９条」）、号証（「甲第３号証」）、文献の著者（「芦部信喜『憲法』」）の中からは拾いません。

## Word の文書で処理する場所

- 本文・表・ヘッダー・フッター・脚注・文末脚注・テキストボックス・振り仮名・数式・図形とグラフの文字・SmartArt
- 名前が太字と普通の字で分かれていても（文字の書式の切れ目をまたいでも）置き換える。置き換えなかった字の書式はそのまま残る
- 変更履歴はすべて承諾した形にする。削除された文字は消す（Word で見えなくても、ファイルの中には残っていて、後で復活することがある）
- コメント、コメント・変更履歴の作者の一覧、XML のコメントを消す
- 作成者・最終更新者・会社名・テンプレートのパス・文書変数・差し込み印刷のデータ元・文書の識別子・rsid・編集の制限の編集者・サムネイル画像・プリンタの設定を消し、作成・更新の日時をいまに置き換える
- リンク先（mailto: など）、フィールドコード（フィールドごと）、画像の代替テキスト、表の代替テキスト、ドロップダウンの項目、カスタム XML、古い VML の図形も伏せる
- 埋め込みの Excel（グラフの元データ）の中も伏せ、画像の付帯情報（EXIF・XMP など。撮影者・作成者・撮影場所）を取り除く
- 別の文書を丸ごと埋め込んだ部分（altChunk）と Strict 形式の Word は伏せきれないので、作らずに止める（Word で保存し直すと扱える）

## PDF の墨消し

文字の層（テキスト）がある PDF だけを扱います。黒い四角を上に重ねるだけでなく、下の文字を取り除きます（重ねるだけの黒塗りは、下の文字をコピーできてしまいます）。黒塗りに重なる画像の部分も塗りつぶすので、OCR 済みのスキャン PDF でも画像の字が消えます。

- 行末で折り返した名前や、均等割付で1字ずつ離れた名前にも当たる
- ページの外・切り抜きの外・非表示のレイヤに置かれた文字も読んで伏せる
- 字を取り除く範囲は字の芯の高さだけにして、行間が詰まった文書でも上下の行の字を消さない
- 注釈・リンク・しおり・添付ファイル・フォーム・文書情報・XMP・名前付き宛先・構造ツリー（代替テキスト）・ページラベル・XFA を消し、レイヤの名前を伏せる

スキャンしただけの PDF（文字の層がない）と、フォントに文字の対応表が無く読むと文字化けする PDF は伏せられないので、不合格にします。OCR をかけてから使ってください。

## 検査の中身

`apply` の後に、出力を機械で検査して報告を作ります。

1. 伏せるはずの原文が出力に残っていないか。本文だけでなく、属性・リンク先・文書情報・ファイル名、Word の全部品をタグを除いてつないだ文字、埋め込みの文書の中、中を読めない部品のバイト列（3字以上の原文）、PDF の全オブジェクトの文字列まで見る（残っていれば不合格）。置換後の記号が別の原文と同じ（名前の入れ替え）なら、それも残りとして数える
2. 置き換えた記号の直後に漢字が残っていないか（姓だけ置き換わって名が残った形。「Ｘ花子」）
3. 電話・メール・郵便番号・口座・生年月日・番号の形が残っていないか
4. 出力を洗い直して、一覧に無い人名・社名が出てこないか
5. 判例・条文・号証の数が入力と同じか（伏せすぎて中身を壊していないか）
6. 段落数（行数・頁数）が入力と同じか
7. Word の変更履歴・コメント・作者などが残っていないか
8. 置換が1件も無いときは「要確認」にする（一覧と文書の取り違え、文字として読めない文書のことがある）

## できないこと

- 画像の中の文字（印影・写真・スキャンした書類）。画像の数は報告に出ます
- 旧形式の Word（.doc）・一太郎・Excel。Word で .docx に保存し直してから使ってください
- 文脈から人が特定されること（珍しい事実関係・職業・日付の組合せ）は防げません
- 手がかり（役割語・敬称・漢字の名前）の無い英字だけの氏名、法人格も決まった屋号も無い社名は、拾えないことがあります（一覧に足してください）
- 裁判所の正式名で書いた事件番号の引用（「大阪高等裁判所平成３０年(ネ)第１２３号控訴事件」）は、自分の事件の表示と見分けがつかないので伏せる側に倒します
- テキストのファイルで、行の途中で改行された名前（「山田\n太郎」）

## 注意

- 候補一覧と検査の報告には、伏せる前の名前が載っています。これ自体が対応表なので、外に出さないでください
- 検査の「合格」は、機械が見つけられなかったという意味です。外に出す前に、必ず全文を目で読んでください
- 機械の検査は、一覧に載っている名前と決まった形のものしか確かめられません

## 開発

```
py -m pip install -e ".[all,dev]"
py -m pytest
```

試験の文書（`tests/fixtures.py`）の名前・住所・番号は、すべて架空のものです。

GitHub に push すると、Windows の実行環境で試験を回し、EXE を作り、できた EXE で伏せて名前が残らないかまで確かめます（`.github/workflows/windows-exe.yml`）。`v` で始まるタグを付けると、zip をリリースに載せます。
